# Принципиальные решения

## 1. Выбор типов данных: `int` для количества, `double` для цены и скидки

**Решение.**
- `quantity` (количество) - `int`: товар продаётся поштучно, дробное количество не имеет смысла.
- `unitPrice` (цена) - `double`: цена содержит копейки (например, `2490.50`).
- `discountPercent` (скидка) - `double`: скидка может быть дробной (например, `12.5 %`).
- Все рассчитанные суммы - `double`, так как получаются из цены и процентов.

**Ограничение `double` для денег.** `double` хранит числа в двоичном виде, поэтому многие десятичные дроби представлены неточно: `0.1 + 0.2 = 0.30000000000000004`. При множестве операций такие погрешности накапливаются. В проекте это учтено так:
- результат выводится с округлением до двух знаков (`printf("%.2f")`);
- в `SelfCheck` дробный итог сравнивается не через `==`, а с допуском: `Math.abs(actual - expected) < 0.001`.

**Почему не `BigDecimal`.** Для реальных денежных расчётов правильнее использовать `BigDecimal` (точная десятичная арифметика) или хранить суммы в копейках в `long`. В этой работе используется `double`, так как он задан сигнатурами методов исходного проекта, а цель работы - освоить примитивные типы.

## 2. Бизнес-правила вынесены в константы класса `OrderCalculator`

**Решение.** Все числовые правила задачи объявлены один раз в виде констант `private static final`:

| Константа | Значение | Смысл |
|---|---|---|
| `VAT_RATE` | 20 | ставка НДС, % |
| `QUANTITY_MAX` | 10 000 | максимальное количество |
| `UNIT_PRICE_MAX` | 5 000 000 | максимальная цена единицы, руб. |
| `DISCOUNT_PERCENT_MAX` | 45 | максимальная скидка, % (вариант 8) |

**Почему.** Индивидуальный вариант (№ 8) меняет одно правило - максимальную скидку (с 30 % до 45 %). Если бы порог был записан числом в нескольких местах, при изменении требования его пришлось бы искать по всему коду, и легко было бы пропустить одно из мест. Сейчас изменение требования - это правка одной строки; `isValid` и `main` используют константу и подхватывают новое значение автоматически. Нижние границы (`> 0`, `>= 0`) оставлены в коде, так как они следуют из смысла величин и не меняются по вариантам.

**Проверка.** Граничные значения покрыты в `SelfCheck` (0/1/10000/10001 для количества, 0/5000000/5000000.01 для цены, -1/0/45/46 для скидки). При изменении порога соответствующие проверки сразу показывают `FAIL`.
